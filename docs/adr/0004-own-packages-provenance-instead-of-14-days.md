# 0004. 자체 패키지는 14일 규칙 대신 출처 확인으로 검증

- 상태: 제안 (이슈 #1)
- 날짜: 2026-10-22

## 맥락

외부 패키지는 "릴리스 후 14일 경과" 규칙을 지켜야 한다. 공급망 공격으로 오염된 버전이 발견되고 회수될 시간을 벌기 위해서다. 자체 패키지(`@sirloinbh/*`)에도 이 규칙을 적용하면, 설정을 한 번 고칠 때마다 하위 반영이 최소 2주 늦어진다. 하지만 자체 패키지도 토큰이 유출되면 오염될 수 있으므로 검증 없이 믿을 수는 없다.

## 결정

자체 패키지는 14일 규칙에서 제외한다. 대신 sync가 PR을 열기 전에 다음 조건을 모두 확인한다.

1. 중앙 리포의 `publish.yml`이 태그 트리거로 publish한 버전이다. 로컬 publish는 금지한다.
2. 패키지 버전과 git 태그(`<pkg>/v<version>`)가 일치하고, 그 태그의 GitHub Release에 publish 실행 URL과 커밋 SHA가 있으며, 그 실행이 성공했다.
3. 동기화 PR 본문에 해당 버전의 CHANGELOG와 중앙 커밋 SHA를 적는다.
4. 하위 `standards-check`가 설치된 패키지에 설치 스크립트가 없고 `dependencies`가 0개인지 다시 검사한다.

자체 패키지가 요구하는 외부 `peerDependencies`에는 기존 규칙(고정 버전, 14일 경과, `--ignore-scripts`, 사전 검증)을 그대로 적용한다. 1단계 peer는 모두 이미 하위 리포에 설치된 버전이다.

## 결과

- 자체 설정 변경은 병합 직후 동기화 PR로 나갈 수 있다.
- GitHub Packages는 npm provenance를 지원하지 않는다. 그래서 출처 확인은 GitHub Release와 Actions 실행 기록에 의존한다.
- 패키지에 의존성과 설치 스크립트가 없으므로, 오염되더라도 설치 시점에 코드가 실행되지 않는다. 남는 위험은 lint·build 시점에 실행되는 설정 코드(eslint-config 팩토리)다. 이 위험은 PR 본문의 CHANGELOG와 diff 링크를 사용자가 검토해서 줄인다.
