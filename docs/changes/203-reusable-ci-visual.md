# #203 Add screenshot comparison and a deploy script check to the shared app CI

## Change

| File | Content |
|---|---|
| `.github/workflows/reusable-app-ci.yml` | Added the inputs `e2e-visual` and `playwright-image`. When `e2e-visual` is set, an `e2e-visual` job runs the e2e tests in a pinned Playwright container with `E2E_VISUAL=1` instead. On failure it uploads `playwright-report` (plus `test-results`) and the baseline-image candidates as the `visual-baselines` artifact. Added a syntax check (`bash -n`) for `deploy/*.sh` to the verify job |
| `templates/app/.github/workflows/ci.yml.tmpl` | Passes the new inputs from the registry and `versions.json` |
| `versions.json`, `versions.schema.json` | Added `images.playwright` (pinned by digest, new `pinnedImage` format) |
| `registry/projects.json`, `registry/projects.schema.json` | Added `features.e2eVisual`. Only workout-memo has `true` |
| `docs/test-config.md`, `docs/design.md` | Describe the screenshot comparison flag and the CI job |
| `scripts/test/scaffold.test.mjs` | Added the new required flag to the fixture |

## Decisions

- Use the same image (`v1.63.0-noble`, same digest) as the existing workout-memo CI (#113), so the existing baseline images can be reused.
- Baseline candidates are generated by running the whole e2e suite with `--update-snapshots=changed`, not a specific spec. Only changed screenshots are regenerated, so the result is the same, and we do not need to know each app's file names.
- The Playwright image has no `psql`. The `e2e-visual` job runs only `npm run db:migrate`; the verify job keeps checking that running it again is safe.
- Apps without deploy scripts (such as infra) skip the check through `nullglob`.
