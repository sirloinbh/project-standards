## 정한 것

- 생성 패키지를 더하지 않고 직접 만든 코드로 계약을 읽는다. 생성 결과를 파일로 커밋하지 않고 테스트가 실행될 때 만든다(계약이 바뀌면 바로 따라감).
- 쓰는 법: 테스트 파일에서 `const api = setupContractApi({ emptyBody: [] })`, 데이터는 `api.use(...contractHandlers({ 'GET /api/machines': [...] }))`. 기존의 `mockApi`(fetch 대체) 테스트는 그대로 둔다.
- 계약에 없는 요청은 그 `fetch`를 실패시키고, 화면이 오류를 삼켜도 테스트가 끝날 때 실패로 만든다. 계약에 없는 API를 화면이 부르는 것을 막는다.
- 이름은 `setupContractApi`다. `use…`로 시작하면 `react-hooks/rules-of-hooks`가 테스트 파일 최상단 호출을 오류로 본다.
- msw 3에서 `onUnhandledRequest`는 `onUnhandledFrame`으로 바뀌었다.
- workout-memo 계약에는 성공 응답 스키마가 아직 없다(설명만 있음). 그래서 기본 응답은 본문이 비어 있고, `emptyBody`와 덮어쓰기로 채운다. 계약 생성(`backend/src/openapi.ts`)에 응답 스키마를 더하면 샘플이 자동으로 채워진다.

## 확인

- workout-memo `main` 작업 폴더(설치된 msw 3.0.3)에서 `contract-api.test.ts` 6개와 화면 테스트 `machines.contract.test.tsx`(머신 라이브러리, 백엔드 없이) 통과. `typecheck`·ESLint·Prettier 통과
- 계약 밖 요청을 `catch`로 삼키는 테스트가 실패하는 것을 확인
- `npm run check`: PR 본문에 기록
