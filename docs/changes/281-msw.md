# #281 Build MSW mocks from the OpenAPI contract to test the frontend without a backend

## Change

| File | Content |
|---|---|
| `templates/msw/frontend/src/test/contract-api.ts` | New feature folder. Builds MSW handlers for every path and method in `docs/openapi.json`. Responses are samples built from the example or schema of the first 2xx response |
| `templates/msw/frontend/src/test/contract-api.test.ts` | Checks the sample rules, relative URLs, per-test overrides, and failure for requests outside the contract in app CI |
| `sync.config.json`, `registry/projects.schema.json`, `registry/projects.json` | `features.msw`. Only workout-memo turns it on |
| `templates/app/.prettierignore.tmpl` | The two managed files |
| `scripts/test/msw.test.mjs` and others | Registry and template checks, snapshot |

## Decisions

- We do not add a code generation package; our own code reads the contract. The generated result is not committed as a file but built when the tests run (so it follows contract changes right away).
- How to use: in a test file, `const api = setupContractApi({ emptyBody: [] })`, and for data, `api.use(...contractHandlers({ 'GET /api/machines': [...] }))`. Existing `mockApi` (fetch replacement) tests are left as they are.
- A request outside the contract makes that `fetch` fail, and even if the screen swallows the error, the test is made to fail at the end. This stops screens from calling APIs that are not in the contract.
- The name is `setupContractApi`. If it started with `use…`, `react-hooks/rules-of-hooks` would treat a top-level call in a test file as an error.
- In msw 3, `onUnhandledRequest` was renamed to `onUnhandledFrame`.
- The workout-memo contract has no success response schemas yet (only descriptions). So the default response has an empty body, and `emptyBody` and overrides fill it. Adding response schemas to the contract generation (`backend/src/openapi.ts`) will fill in the samples automatically.
