# #352 Apply the vite 6.4.5 security patch

## Change

| File | Content |
|---|---|
| `versions.json`, `docs/versions.md` | frontend `vite` 6.4.4 to 6.4.5 |

## Why

- `npm audit` reports [GHSA-8g5g-mxqh-grgj](https://github.com/advisories/GHSA-8g5g-mxqh-grgj) (medium, `server.fs.deny` bypass) in vite 6.4.4. Only 6.4.4 is affected, and it was fixed in 6.4.5.
- It applies only to the dev server. The app dev server is open only on localhost and is not in the production image.

## Exception to the 14-day rule

- 6.4.5 was published on 2026-10-21, so it is 10 days old on the day of this change (2026-10-31). It does not meet "14 days after release" (2026-11-04) in `docs/dependency-policy.md`.
- The user was told this and decided on 2026-10-31 to proceed with an exception this once.

## Conditions checked

| Condition | Result |
|---|---|
| Exact version | 6.4.5 |
| Install scripts | None |
| Publisher and repository | `github.com/vitejs/vite`, published by GitHub Actions, attestation present |
| Dependencies | Same as 6.4.4 |
| Packages used together | `vitest` 5.0.3 (peer `^6.4.0`) and `@tailwindcss/vite` 4.3.3 (peer `^6`) are within range |

## What to do in the sync PRs

The sync PR changes only the app `package.json`, so `npm ci` in CI fails until the lockfile is matched. The user runs the approved install (`docs/dependency-policy.md`). On each PR branch, run `npm install --ignore-scripts --package-lock-only` and `npm run lockfiles:sync`, then commit.

The english-study in the issue is the repo renamed to cert-manager, so the targets are the 8 apps.
