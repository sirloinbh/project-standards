## 앱에서 확인한 zod 4 차이

앱 코드를 옮기며 전환 전과 4.6.7을 비교했다. 새 앱을 만들 때도 같은 점을 조심한다.

- `.default()`를 `.optional()`이나 `.partial()`로 감싸도 기본값이 적용된다. PATCH 스키마는 기본값 없는 shape에서 만든다.
- 문자열 `.min()`, `.max()`는 `.length`가 있는 입력이면 타입 실패 뒤에도 돌아 문구가 덧붙는다. 코드 포인트로 세므로 이모지 길이도 달라진다. 문구를 지키려면 `.refine`을 쓴다.
- 배열 `.max()`는 `.refine`보다 앞에 둔다. 그래야 원소를 읽기 전에 거절한다.
- `z.number()`는 `Infinity`를 타입 단계에서 거절해 뒤의 `.refine`이 돌지 않는다.
- `z.uuid()`는 전에 통과하던 값을 거절할 수 있다. 같은 범위가 필요하면 `z.guid()`를 쓴다.
- `datetime` 검사가 더 엄격하다. 초 없는 시각과 콜론 없는 시차를 거절한다.

## 동기화 PR에서 할 일

동기화 PR은 앱 `package.json`만 바꾸므로 잠금 파일을 맞출 때까지 CI의 `npm ci`가 실패한다. 승인된 설치는 사용자가 실행한다(`docs/dependency-policy.md`). 각 PR 브랜치에서 `npm install --ignore-scripts --package-lock-only`, `npm run lockfiles:sync`를 실행해 커밋한다.

workout-memo만 `frontend/package.json`에도 zod가 있고, 이 필드는 중앙 관리 대상이 아니다. 그대로 두면 프런트가 3.25.76에 남아 같은 `shared/contract.ts`의 결과가 프런트와 백엔드에서 갈린다(`.max(2)`에 이모지 2개를 넣으면 3.25.76은 거절, 4.6.7은 통과). workout-memo의 동기화 PR에서는 프런트 zod도 4.6.7로 올린 뒤 잠금 파일을 맞추고 프런트 테스트를 확인한다. `chromium-bidi` 14.0.0이 `zod ^3.24.1`을 요구해 잠금 파일에 3.25.76이 개발 의존성으로 남을 수 있다. 실제 결과와 알림이 닫히는지는 잠금 파일을 맞춘 뒤 확인한다.

앱 코드 전환이 main에 들어간 뒤 병합한다. 2026-11-01 기준 workout-memo #195만 병합 전이다. CI가 이 순서를 막아 준다고 믿지 않는다. cert-manager, money-ledger, dev-career-portfolio는 전환 전 코드도 4.6.7에서 타입 검사를 통과했다. workout-memo는 `required_error` 등 zod 3 문법이 남아 있어 전환 전에는 깨질 것으로 보지만 직접 돌리지는 않았다.
